# Isolated media-interlude capability spike: audio-duck, MediaSession pause/play, fullscreen overlay (v1)

The spike adds a self-contained `:mediaexperiment` Android TV app that gathers evidence for three physical questions — can the companion duck audio while another app plays, pause/resume the active MediaSession with observed confirmation, and show a local fullscreen overlay video while the other app stays paused — without touching production code. The design splits an Android-free decision core (an interlude state machine plus a fail-closed safe-resume guard) from thin Android ports, so the resume safety rules are exhaustively unit-testable on the JVM. The automated gate (build, lint, 17 JVM tests) is green here, and the report honestly separates what is IMPLEMENTED, what is AUTOMATED-PASS, and what remains physically UNTESTED, making no claim about real ducking or a real Prime pause. The one deliberate, documented delta is the single `include(":mediaexperiment")` line that trips 14 M4/M5 byte-pin/inventory boundary assertions; the baselines and guards were left untouched by choice.

Watch for: the `emergencyCleanup` resume path exists in the guard and is unit-tested but is never actually constructed by the state machine — every teardown path tears down without resuming (confirmed; this is *safer* than the spec, flagged so it is a conscious decision, not a latent gap). Everything else — sent≠confirmed gating, same-identity re-check at resume, idempotent cleanup, isolation, forbidden-mechanism absence, manifest shape — holds up under reading.

**Verdict**: APPROVED

## High-level view

The correctness heart is `SafeResumeGuard.mayResume`, a pure boolean over the original target, recorded pause-ownership facts, and the latest observed snapshot. It fails closed on every missing precondition: no PLAY unless this POC both sent *and* observed the pause, the latest snapshot is non-null and on the same package, and media identity still matches. `InterludeStateMachine` enforces the ordering around it — a dispatched pause only advances the interlude after an observed `STATE_PAUSED`, a missed confirmation becomes `PAUSE_TIMEOUT` and stops, and any error or stop converges on `STOPPED` with overlay removed and focus abandoned.

The spec says resume is allowed when the interlude ended normally "or during explicit emergency cleanup." The guard honors both, but the state machine only ever attempts resume on the normal `onVideoCompleted` path; `stop()` and `onVideoError` tear down and never call the resume attempt. The net runtime behavior is strictly more conservative than the spec (emergency never auto-resumes), which is the safe direction, but the `emergencyCleanup=true` branch is dead code in production and lives only in a guard unit test.

Isolation holds: distinct `applicationId`, its own notification-listener component and access check, its own FGS and channel id, no `project(':app')` dependency, no shared prefs/Cloud/BootReceiver, and zero files changed under `app/`. The manifest declares exactly the mediaPlayback FGS, `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, and `SYSTEM_ALERT_WINDOW`, and omits `INTERNET`/`RECEIVE_BOOT_COMPLETED`. Transport is MediaSession-only — no accessibility, input injection, adb, coordinate injection, UI scraping, or programmatic stream-volume change anywhere in source.

Tests meaningfully exercise the core: recording ports assert exact `pause()`/`play()` counts, so `play()==0` in every failure scenario and `play()==1` only on the fully-confirmed-owned happy path. All nine required scenarios are present and would fail if the gating logic were reverted. The known boundary-test delta (settings.gradle byte pin + docs inventory) is an honest, documented consequence of registering an installable module, not a worked-around failure.

### Fail-closed resume guard and the sent≠confirmed boundary

`SafeResumeGuard.mayResume` rejects on any missing precondition before it can reach `return true`: target or ownership null, pause not sent, pause not confirmed, interlude neither ended-normally nor emergency, no latest snapshot, package mismatch, or identity mismatch. `InterludeStateMachine` enforces the ordering: `sendPause()` sets `pauseSent` and arms a deadline, but only an observed `STATE_PAUSED` on the same package flips `pauseConfirmed` and advances. A dispatch never observed becomes `PAUSE_TIMEOUT` and goes straight to cleanup, so a sent-but-unconfirmed pause can never authorize PLAY. The identity comparison (`PocMediaIdentity.sameMedia`) is itself fail-closed: when a stable `mediaId` is present on both sides it is authoritative, otherwise it falls back to normalized title/subtitle matching and a duration tolerance, returning false whenever evidence is thin — the behavior that defends against resuming into a changed episode or a different show in the same app.

### The emergency-cleanup resume branch is never driven at runtime

The spec permits resume either when the interlude ended normally or "during explicit emergency cleanup." The guard models both via `PauseOwnership.emergencyCleanup`, and `SafeResumeGuardTest.emergencyCleanupAllowsResumeWhenOtherwiseOwned_true` locks the branch in. But in the state machine the only call that builds `PauseOwnership` is `attemptResume()`, reached solely from `onVideoCompleted` (normal end), and it always passes `emergencyCleanup=false`. `stop()` and `onVideoError` call `cleanup()` directly and never attempt resume. So at runtime the emergency path tears everything down and leaves the stream paused rather than resuming — strictly safer than the spec, since an auto-PLAY during an error teardown is the riskier behavior. The observation worth recording is only that the guard's emergency branch is production-dead and exercised exclusively by a unit test; a reviewer should know the narrowing is intentional rather than assume the emergency-resume path is live.

### Resume re-checks a live snapshot, seeded from a pre-pause sample

`attemptResume()` evaluates the guard against `lastSnapshot`, which `observe()` keeps current from the service's 1-second sampler. `beginSequence` seeds it once with the pre-pause (typically PLAYING) snapshot so the guard has something to read, and each sampler tick overwrites it with a fresh sample of the selected controller. Because resume is only reachable after the interlude plays — several sampler ticks later — the stale seed is overwritten long before any PLAY. The dependency is subtle enough to call out: resume safety relies on the sampler having refreshed `lastSnapshot` to a genuinely current reading, which is a device-timing property that cannot be verified in the sandbox and should be watched during physical testing.

### Isolation and forbidden-mechanism posture

`git diff` against the base shows zero files changed under `app/`; the only shared-file edit is the single `include(":mediaexperiment")` line in `settings.gradle`. The module declares its own `applicationId`, its own `ExperimentMediaAccessService` notification-listener plus `ExperimentNotificationAccess` check (reading `enabled_notification_listeners` directly, with a documented rationale for Sony TV builds), its own FGS and notification channel id, and no `project(':app')` dependency. A source grep for accessibility, input/coordinate injection, adb, `setStreamVolume`, UI scraping, `INTERNET`, `RECEIVE_BOOT_COMPLETED`, `PackageInstaller`, and `SharedPreferences` finds only negating comments and build artifacts — none in live code. Transport flows exclusively through `MediaController.getTransportControls()`, and `AndroidAudioFocusPort` only requests/abandons `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` with `USAGE_ASSISTANT`/`CONTENT_TYPE_SPEECH`, never altering stream volume.

### Manifest and FGS correctness

The manifest declares the `mediaPlayback` foreground service with `FOREGROUND_SERVICE_MEDIA_PLAYBACK` + `FOREGROUND_SERVICE`, and `SYSTEM_ALERT_WINDOW` for the overlay — the honest service type for an app that actually pauses/plays media and renders a media overlay, distinct from `:app`'s `specialUse`. `InterludeService` starts foreground with `FOREGROUND_SERVICE_TYPE_MEDIA_PLAYBACK` on API ≥ 29 and the 2-arg form below, matching the manifest type, and stops itself if overlay permission is absent. The overlay uses `TYPE_APPLICATION_OVERLAY` gated on `Settings.canDrawOverlays` (throwing to the error path when ungranted, which routes to emergency cleanup), plays only the bundled local asset with no network source, and tears the window/player/surface down idempotently.

### Test coverage against the decision core

The tests are behavioral, not static: recording ports count `pause()`/`play()`/`attach()`/`abandon()` calls, so each scenario asserts the real dispatch decisions of the actual `InterludeStateMachine`/`SafeResumeGuard`. The happy path asserts exactly one PLAY and a confirmed resume; focus-denied, pause-timeout, session-replacement, media-identity-change, overlay-failure, repeated-stop, out-of-order-complete, and sent≠confirmed all assert `play()==0`. These would fail if the gating were reverted (e.g. if a sent pause were treated as confirmed, or the guard skipped the identity check). All nine required scenarios are present. Not tested here, and correctly disclaimed in the report: real audio ducking, a real Prime `PlaybackState` transition, and real overlay rendering — none are observable without a device, and the report claims none of them PASS.

### Known boundary-test delta

Registering an installable module necessarily edits the single tracked `settings.gradle`, whose bytes are pinned by 10 M4/M5 provenance assertions, and adding the report file trips 4 more docs-inventory assertions — 14 total, all citing only the settings line or the new doc, none touching production/M5 bytes. The author left the baselines, boundary tests, and `app/` bytes untouched rather than editing a release guard to force green. That judgment is sound: an honest, documented delta on an experimental branch is preferable to mutating a provenance guard, and the failures are fully attributable and benign. The `:mediaexperiment` tree sits outside the guards' inventory scope, so M5 physical qualification is unaffected.
